# ТЗ и инструкция по верстке фронтенд-интерфейса экрана кухни (Kitchen Display System — KDS)

Данный документ описывает интерфейс экрана кухни (KDS) и порядок его интеграции с ранее описанным терминалом официанта. Документ структурирован для скорейшей передачи AI-агенту с целью верстки на Svelte/React + Tailwind CSS.

---

## 1. Глобальное состояние экрана кухни (KDS State Schema)

```typescript
type KdsItemStatus = 'pending' | 'cooking' | 'ready' | 'out_of_stock';

interface KdsOrderItem {
  id: string;
  precheckId: string;
  precheckNumber: number;
  guestName: string;
  title: string;
  quantity: number;
  comment?: string; // Пожелания (без лука, прожарка и т.д.)
  status: KdsItemStatus;
  createdAt: string; // ISO Timestamp создания заказа
  isCustom?: boolean;
}

interface KdsPrecheckCard {
  precheckId: string;
  precheckNumber: number;
  waiterName: string;
  hallName: string;
  createdAt: string; // ISO Timestamp
  items: KdsOrderItem[];
  status: 'active' | 'closed';
}

interface KdsState {
  kitchenWorkerName: string; // "Привет, Алексей"
  cards: KdsPrecheckCard[];
  filterStatus: 'all' | 'delayed'; // Опциональный фильтр
}

```

## 2. Экраны и компонентная структура KDS

### 2.1. Шапка экрана (Header Bar)

* **Левая часть**:
* Текст: `Привет, {kitchenWorkerName}` (Font-weight: 600, Text-xl).
* Статичный индикатор локации: `[ 🍳 Мы на кухне ]` (Высококонтрастный бейдж).


* **Центральная часть**:
* Таймер смены / Текущее время (`14:32`).
* Счетчик активных заказов (`В очереди: N`).


* **Правая часть**:
* Индикатор сетевого соединения / WebSocket (`🟢 В сети` / `🔴 Офлайн`).
* Кнопка фильтрации задерживающихся блюд (`[ ⚠️ Задержки (>10 мин) ]`).



---

### 2.2. Основная область: Сетка заказов (Card Grid View)

Заказы выстраиваются в сетку (3–4 колонки в зависимости от диагонали KDS-планшета/монитора). Порядок сортировки: **First In, First Out (FIFO)** — самые старые заказы слева сверху.

```
+-----------------------------------------------------------------------+
|  Привет, Иван | 🍳 Мы на кухне                  14:32 | 🟢 В сети     |
+-----------------------------------------------------------------------+
| ┌───────────────────────────┐ ┌───────────────────────────┐           |
| │ Пречек №104      ⏳ 12:45  │ │ Пречек №105       ⏳ 04:12  │           |
| │ Официант: Цыцыгма (Зал 1) │ │ Официант: Цыцыгма (Зал 1) │           |
| ├───────────────────────────┤ ├───────────────────────────┤           |
| │ [!] Стейк Рибай      x1   │ │ Борщ Сибирский       x2   │           |
| │     (клик -> поп-ап)      │ │                           │           |
| │                           │ │ Морс Клюквенный      x1   │           |
| │ [✅] Борщ Сибирский  x1   │ │                           │           |
| └───────────────────────────┘ └───────────────────────────┘           |
+-----------------------------------------------------------------------+

```

#### Анатомия карточки пречека (`KdsPrecheckCard`):

1. **Заголовок карточки**:
* Номер пречека (`№104`).
* Имя официанта и название зала (`Цыцыгма / Основной зал`).
* **Плашка таймера (Elapsed Time)**: Отображает время, прошедшее с момента отправки заказа на кухню (`MM:SS`).


2. **Логика цветовой индикации по времени (Latency Highlighting)**:
* **$0$ – $10$ минут**: Стандартное оформление (нейтральный темный/светлый фон карточки).
* **Более $10$ минут**: Карточка и таймер автоматически меняют цвет на **насыщенный оранжевый** (`bg-orange-600/20`, `border-orange-500`). Заголовок вибрирует/пульсирует для привлечения внимания.


3. **Список позиций**:
* Каждая позиция представляет собой нажимаемую плашку во всю ширину карточки (высота минимум $48\,\text{px}$).
* Название товара, количество (`x2`), особые комментарии.
* Visual Status:
* `pending`: Стандартный вид.
* `ready`: Зачеркнутый/полупрозрачный текст с зеленой галочкой `[✅]`.
* `out_of_stock`: Перечеркнутый красным текст с иконкой `[❌ Нет блюда]`.





---

### 2.3. Всплывающее окно действия (Item Action Modal/Popover)

При клике/тапе по конкретной позиции пречека поверх открывается модальное окно с выбором действия:

```
+---------------------------------------------------+
|               Позиция: Стейк Рибай                |
|             Пречек №104 (Гость 1: Слава)          |
+---------------------------------------------------+
|  [  ✅ ГОТОВО  ]         |  [  ❌ НЕТ БЛЮДА  ]    |
|  (Зеленая кнопка)        |  (Красная кнопка)      |
+---------------------------------------------------+
|                     [ Отмена ]                    |
+---------------------------------------------------+

```

#### Механика обработки нажатий:

1. При нажатии **`[ ✅ ГОТОВО ]`**:
* Статус позиции в БД меняется на `ready`.
* Позиция на экране кухни визуально помечается как готовая (зеленый маркер / зачеркивание).
* Отправляется WebSocket-событие на терминал официанта.


2. При нажатии **`[ ❌ НЕТ БЛЮДА ]`**:
* Статус позиции меняется на `out_of_stock`.
* Позиция подсвечивается красным на кухне.
* На терминале официанта выводится алерты и уведомление.

## 3. Интеграция с экраном официанта (Real-time Synchronization)

Связь между терминалом кухни и терминалом официанта осуществляется по протоколу WebSocket.

```
 [ Экран Кухни (KDS) ]                                 [ Экран Официанта (POS) ]
           │                                                       │
           │ ──(Клик "ГОТОВО")───────────────────────────────────> │
           │    WS Event: ITEM_STATUS_CHANGED                      │
           │    { precheckId: "104", status: "ready" }             │ Отображает зеленый балун
           │                                                       │ [ 🟢 1 готово ] в списке
           │                                                       │
           │ <──(Официант закрыл и оплатил пречек)──────────────── │
           │    WS Event: PRECHECK_CLOSED                          │
           │    { precheckId: "104" }                              │
           │                                                       │
  Карточка №104 автоматически                                      │
  удаляется с экрана кухни                                         │

```

### Изменения на экране официанта:

1. **Список активных пречеков**:
* На карточке пречека появляется **зеленый балун** с количеством готовых позиций, готовых к подаче (например, `🟢 2`).
* Если по пречеку есть статус `out_of_stock`, появляется **красный балун** (`🔴 1 ошибка`).


2. **Внутри открытого пречека**:
* Рядом с конкретной позицией отображается статус: `[ Готово ]` (зеленый чекбокс) или `[ Нет блюда ]` (красный лейбл с предложением удалить/заменить позицию).


3. **Автоматическое удаление заказа с кухни**:
* Как только официант рассчитывает всех гостей и пречек переходит в статус `closed`, сервер отправляет событие `PRECHECK_CLOSED`.
* Экран кухни плавно убирает (Fade-out animation) соответствующую карточку из сетки.

## 4. Пайплайн состояний и UX-оптимизация кухни

### А. Цветовая матрица состояний (Color System)

| Состояние / Условие | Цвет / Стиль (Tailwind CSS) | Назначение |
| --- | --- | --- |
| **Время $0$–$10$ мин** | `bg-slate-800`, `border-slate-700` | Стандартный активный заказ |
| **Задержка $>10$ мин** | `bg-amber-950/40`, `border-amber-500` | Превышение норматива приготовления |
| **Блюдо готово (`ready`)** | `bg-emerald-950/30`, `text-emerald-400` | Фиксация готовности |
| **Нет блюда (`out_of_stock`)** | `bg-rose-950/40`, `text-rose-400` | Стоп-лист / Ошибка наличия |

### Б. Оптимизация для жестких условий кухни (KDS UX Best Practices)

1. **Крупные Touch-зоны**: Экраны кухни часто монтируются на стену или стоят на подставках. Все элементы управления имеют минимальный размер $56 \times 56\,\text{px}$.
2. **Звуковое оповещение (Audio Alerts)**:
* При поступлении нового пречека проигрывается короткий звуковой сигнал (Chime).
* При переходе заказа через порог $10$ минут проигрывается предупреждающий тональный сигнал (Warning Beep).


3. **Защита от случайных кликов**:
* Нажатие на статус "Нет блюда" требует повторного подтверждения в модальном окне, чтобы исключить случайный отказ от блюда во время потока операций.


4. **Режим восстановления (Crash Recovery)**:
* При перезагрузке KDS-планшета текущее состояние восстановленных карточек загружается из локального хранилища/сервера с сохранением исходных счетчиков времени.

# ТЗ и инструкция по верстке фронтенд-интерфейса администратора (POS Admin Terminal)

Настоящее техническое задание описывает устройство, экраны, структуру данных и UX/UI-пайплайны мобильно-адаптированного интерфейса администратора системы POS/KDS.

Дизайн-система полностью наследует стилистику, эргономику и цветовые паттерны экранов официанта и кухни (Mobile-First, Tailwind CSS, крупный touch-target, высокая контрастность).

## 1. Глобальное состояние интерфейса админа (Admin State Schema)

```typescript
type AccessStatus = 'active' | 'suspended' | 'terminated';

interface AdminDevice {
  id: string;
  code: string; // 6-значный код
  deviceName: string; // Напр. "Tablet-Hall-1"
  assignedStaffId: string | null;
  assignedStaffName?: string;
  assignedHallIds: string[];
  status: AccessStatus;
  lastActiveAt: string;
}

interface AdminMenuItem {
  id: string;
  categoryId: string;
  title: string;
  description: string;
  price: number;
  imageUrl?: string;
  isAvailable: boolean; // Доступность в меню (стоп-лист)
}

interface CancelledPrecheck {
  id: string;
  number: number;
  waiterName: string;
  hallName: string;
  totalAmount: number;
  cancelledAt: string;
  cancelledByAdmin: string;
  reasonComment: string; // Обязательный комментарий к отмене
  items: Array<{ title: string; qty: number; price: number }>;
}

interface ShiftSummary {
  shiftId: string;
  openedAt: string;
  closedAt?: string;
  closedBy: string;
  totalRevenue: number;
  paymentBreakdown: {
    cash: number;
    cashless: number;
    debtRepayment: number; // Возврат долга

  byHalls: Record<string, number>;
  byWaiters: Record<string, number>;
  byKitchens: Record<string, number>;
}

interface ExpenseItem {
  id: string;
  createdAt: string;
  category: string; // Напр. "Закупка овощей", "Хоз. нужды"
  amount: number;
  comment?: string;
  author: string;
}

```

## 2. Архитектура навигации и Макета (Layout)

Интерфейс спроектирован для использования с мобильного телефона или планшета администратора (Mobile-First, $375\,\text{px} - 768\,\text{px}$).

### 2.1. Шапка (Header)

* **Верхняя строка**: `Привет, {adminName}` (Font-weight: 600) | Текущая смена: `[🟢 Смена открыта]` / `[🔴 Смена закрыта]`.
* **Фоновый цвет**: Фирменный нейтрально-темный (`#0F172A` / `bg-slate-900`), единый с терминалами.

### 2.2. Нижнее мобильное меню навигации (Bottom Navigation Bar)

Фиксированный подвал высотой $60\,\text{px}$ с 5 основными вкладками:

1. **`[ 📱 Устройства ]`** — управление терминалами и персоналом.
2. **`[ 🍔 Меню ]`** — справочник товаров и категорий.
3. **`[ 🧾 Чеки ]`** — мониторинг активных пречеков и отмены.
4. **`[ 💰 Смена ]`** — кассовые операции и Z-отчет.
5. **`[ 📊 Отчеты ]`** — аналитика, P&L, финансовые показатели.

### 3.1. Модуль «Устройства и Персонал» (`/admin/devices`)

Обеспечивает привязку планшетов/смартфонов и оперативный контроль доступа сотрудников.

```
┌─────────────────────────────────────────────────────────────┐
|  Терминал #01 (iPhone 13)                 [ 🟢 Активен ]    |
|  Код: 849-201 | Официант: Цыцыгма | Залы: Главный, Терраса  |
|  [ ✏️ Изменить ]    [ ⏸ Приостановить ]   [ 🚫 Уволить ]     |
└─────────────────────────────────────────────────────────────┘

```

#### Функционал и действия:

1. **Привязка нового устройства**:
* Кнопка `[ ➕ Привязать новое устройство ]`.
* Поле ввода 6-значного кода (который высвечивается на Экран 0 у официанта).
* Селектор выбора сотрудника из списка и чекбоксы закрепленных торговых залов.


2. **Управление доступом**:
* `[ ⏸ Временно отключить ]`: Менять статус на `suspended`. Устройство официанта блокируется с сообщением *"Доступ временно ограничен администратором"*.
* `[ 🚫 Уволить / Удалить ]`: Менять статус на `terminated`.
* **Критический Пайплайн**: На привязанное устройство мгновенно отправляется WebSocket-событие `FORCE_LOGOUT`. Терминал официанта сбрасывает токен и мгновенно переходит на **Экран 0 (Регистрация нового устройства)**.

### 3.2. Модуль «Управление Меню» (`/admin/menu`)

Простой CRUD-интерфейс, оптимизированный под добавление товаров «на лету» прямо со смартфона.

* **Фильтрация**: Горизонтальная полоса категорий (Горячее, Десерты, Напитки...).
* **Карточка товара**:
* Превью изображения ($48 \times 48\,\text{px}$), название, цена, тумблер активности (Стоп-лист).


* **Модальное окно / Экран создания/редактирования товара**:
1. Наименование товара.
2. Категория (Select).
3. Цена ($\text{₽}$).
4. Описание.
5. **Изображение**: Кнопка `[ 📷 Загрузить фото / Задать URL ]`.
6. Тумблер `[ В наличии / Стоп-лист ]`.

### 3.3. Модуль «Контроль Пречеков и Отмены» (`/admin/prechecks`)

Предназначен для мониторинга открытых столов и проведения экстренных отмен.

#### Просмотр активных пречеков:

* Сетка/список всех неоплаченных пречеков по всем официантам.
* Состав заказа, итоговая сумма, время создания.

#### Пайплайн отмены пречека (Cancellation Pipeline):

```
Клик [ ❌ Отменить пречек ]
            │
            ▼
┌─────────────────────────────────────────────────────────────┐
|                  Подтверждение отмены                       |
|  Пречек №104 (Официант: Цыцыгма) — 1 850 ₽                  |
|                                                             |
|  Укажите причину отмены (Обязательно):                      |
|  [ Текстовое поле / Выбор: Ошибка ввода / Отказ гостя ]     |
|                                                             |
|  [ Отмена ]                      [ ⚠️ Подтвердить отмену ]  |
└─────────────────────────────────────────────────────────────┘
            │
            ▼
• Пречек переходит в архив отмененных (CancelledPrecheck).
• С кухни (KDS) мгновенно удаляется карточка заказа.
• Официанту приходит уведомление: "Пречек №104 отменен админом".

```

### 3.4. Модуль «Операции со сменой и Кассовый Отчет» (`/admin/shift`)

Управление кассовой сменой и мгновенный снятие Z-отчета.

#### Финансовая сводка текущей смены:

* **Кассовые поступления**:
* `Наличные`: Сумма ($\text{₽}$).
* `Безналичный расчет (Карты/QR)`: Сумма ($\text{₽}$).
* `Возврат долгов`: Сумма ($\text{₽}$).
* **Итого валовая выручка**: Сумма ($\text{₽}$).



#### Разрез по подразделениям (Акордеон/Таблицы):

1. **По торговым залам**: Зал 1, Зал 2, Терраса (Выручка, кол-во чеков).
2. **По официантам**: Выручка и средний чек на каждого сотрудника.
3. **По кухням/барам**: Нагрузка и сумма приготовленных блюд цехами.

* **Кнопка `[ 🔒 Закрыть смену и сформировать Z-Отчет ]**`: Фиксирует смену в БД, блокирует новые проведения до открытия новой смены.

### 3.5. Модуль «Аналитика продаж и Сравнительные Отчеты» (`/admin/analytics`)

Модуль для оценки динамики торговли с автоматическим сопоставлением периодов.

#### Автоматический расчет исследуемого и прошлых периодов:

1. Пользователь выбирает исследуемый период (например, `01.09.2026 – 07.09.2026` — 7 дней).
2. **Авто-подстановка**: Система автоматически рассчитывает эквивалентный предыдущий период той же длительности (`25.08.2026 – 31.08.2026` — предшествующие 7 дней).

#### Таблица анализа продаж товаров (Product Performance Table):

```
┌─────────────────────────────────────────────────────────────────────────┐
| Товар          | Текущий (Кол/Сум) | Прошлый (Кол/Сум) | Динамика (%)  |
├────────────────┼───────────────────┼───────────────────┼───────────────┤
| Стейк Рибай    | 42 шт / 50 400 ₽  | 35 шт / 42 000 ₽  | 📈 +20.0%     |
| Борщ Сибирский | 120 шт / 45 600 ₽ | 140 шт / 53 200 ₽ | 📉 -14.2%     |
└─────────────────────────────────────────────────────────────────────────┘

```

### 3.6. Модуль «Ведение расходов и Финансовые Показатели (P&L)» (`/admin/finance`)

Позволяет вести учет внекассовых операционных расходов и рассчитывать чистую прибыль заведения.

#### 1. Ввод расходов (Expense Entry):

* Кнопка `[ ➕ Добавить расход ]`.
* Поля: Категория (`Закупка`, `Аренда`, `ЗП`, `Хозтовары`), Сумма, Комментарий.

#### 2. Финансовый отчет Выручка/Расход (Profit & Loss Statement):

$$\text{Чистый Доход} = \text{Валовая Выручка} - \text{Операционные Расходы}$$

$$\text{Рентабельность (Margin \%)} = \left( \frac{\text{Чистый Доход}}{\text{Валовая Выручка}} \right) \times 100\%$$

* **Визуальный блок финансовых показателей**:
* **Выручка**: $1\,250\,000\,\text{₽}$
* **Расходы**: $820\,000\,\text{₽}$
* **Чистая прибыль**: $430\,000\,\text{₽}$
* **Маржинальность**: $34.4\%$

## 4. UI/UX Стандарты таблиц и выгрузки в Excel

Так как администратор работает с мобильных устройств, отображение крупных отчетов подчиняется строгим правилам верстки:

### 4.1. Верстка мобильных таблиц

* **Двухосевой скролл (Horizontal & Vertical Scroll)**:
* Обертка таблицы содержит классы `overflow-x-auto overflow-y-auto max-h-[60vh]`.


* **Зафиксированный заголовок и колонка (Sticky Header & First Column)**:
* Заголовок таблицы (`<thead>`) зафиксирован сверху (`sticky top-0 bg-slate-800 z-10`).
* Первая колонка с названием товара/официанта зафиксирована слева (`sticky left-0 bg-slate-900 z-20`), что позволяет скроллить числовые данные влево-вправо без потери контекста.



### 4.2. Механика экспортных операций (Excel Export)

В шапке каждого отчета присутствует кнопка: `[ 📥 Выгрузить в Excel (.xlsx) ]`.

```
[ Клик по кнопке Excel ]
         │
         ▼
Генерация файла через библиотеку ExcelJS / SheetJS (xlsx)
• Форматирование колонок (ширина, выравнивание чисел по правому краю).
• Подсветка итоговых строк (Bold, цвет фона заголовка).
         │
         ▼
Автоматическое скачивание файла: `Report_Sales_2026-09-09.xlsx`

```

## 5. Интеграция и Безопасность (Real-time Event System)

Все действия администратора мгновенно транслируются на связанные терминалы через WebSocket-сервер:

| Событие Админа | WebSocket Event | Получатель | Реакция интерфейса получателя |
| --- | --- | --- | --- |
| **Отключение устройства** | `DEVICE_BLOCKED` | Терминал Официанта | Принудительный редирект на Экран 0 (Регистрация). |
| **Отмена пречека** | `PRECHECK_CANCELLED` | Официант / Кухня | Удаление заказа из KDS и списка активных пречеков. |
| **Изменение цены/стоп-лист** | `MENU_UPDATED` | Все официанты | Фоновое обновление справочника товаров без перезагрузки. |
| **Закрытие смены** | `SHIFT_CLOSED` | Все терминалы | Блокировка создания новых пречеков до открытия новой смены. |

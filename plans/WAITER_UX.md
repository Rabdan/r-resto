# UX официанта (главный интерфейс)

Терминал официанта — основной рабочий экран R-resto. Телефон 375–430px, портрет, одна рука. Планшет — те же паттерны, плитки в 3 колонки.

Ориентиры: Toast Go (список чеков, split tap-to-move), iikoWaiter (отправка на кухню, статусы, поиск), Poster (плитки). ТЗ: [`idea_waiter.md`](../idea_waiter.md). Нельзя заменить конструктор «списком и формой».

## Принципы

- Thumb zone: главные кнопки внизу (создание, оплата, на кухню).
- Touch ≥ 48×48px.
- Цвет шапки = `halls.color_hex` активного зала.
- Светлая база официанта и кухни (`slate-50`).
- Онлайн обязателен (кухня). Офлайн-очередь не в v1.

## Экран 0 — привязка

Центр: «Привязка терминала», код `XXX-XXX` моноширинно, «Покажи этот код администратору», пульс. По SSE `DEVICE_ACTIVATED` → `/waiter` или `/kitchen`. Ссылка «Вход администратора» → `/admin` (PIN, не код устройства).

## Экран 1 — список заказов

Как Payment Terminal Toast, под узкий экран.

- Шапка: «Привет, {имя}» | селектор зала (если залов > 1) или статичный лейбл.
- Табы: **Активные** / **Закрытые** (закрытые — только текущая смена, read-only). Список по возрастанию времени, сначала старые. Тап по закрытому чеку — просмотр.
- Карточка активного: №, имена гостей, 1–2 позиции превью, сумма **неоплаченного**, возраст, балуны KDS: зелёный «готово N», красный «нет блюда N».
- FAB снизу: **Создать заказ**.

Жесты карточки:

| Жест | Действие |
| --- | --- |
| Тап | конструктор |
| Свайп влево | оплата |
| Свайп вправо | печать |
| Long-press | меню: печать, +гость. Отмена — нет (только админ) |

Свайп не закрывает и не удаляет заказ.

## Экран 2 — заказ / чек

Позиции — основной экран. Меню — нижняя шторка до строки итогов.

```
[ ← ]                              зал
N поз. — 1 850 ₽          [Меню / Свернуть]
позиции по гостям
[+ Гость] [Печать] [На кухню] [ОПЛАТА]
```

Шторка меню (поверх позиций и футера, до строки итогов):

```
[Горячие] [Десерты] [Напитки] ...
плитки 2 колонки, балун = сумма qty по всему заказу
```

Новые блюда добавляются текущему гостю (последний выбранный / первый). Гости живут на экране позиций, не в шторке меню.

Начальное состояние шторки:

- `/waiter/new` — открыта (сразу набор).
- Существующий заказ `/waiter/{id}` — закрыта (сразу позиции и футер).
- Закрытый чек — закрыта, кнопки «Меню» нет, в футере только «Печать».

### Черновик заказа

«Создать заказ» открывает **черновик** (`/waiter/new`) — в БД ничего не пишется. Заказ сохраняется только при первом **«На кухню»** (`fired`) или **«Оплата»** (сразу оплата). После сохранения официант переходит на `/waiter/{id}`, шторка меню закрывается, дальнейшие изменения сохраняются автоматически. Пустой/брошенный черновик пропадает без следа.

### Экран позиций

- Под шапкой зала — строка итогов: количество позиций и сумма. Кнопка **Меню** / **Свернуть** (нет на закрытом чеке).
- Список: группировка по гостю. `+`/`−`. Перенос другому гостю жестом. Удаление только `held`.
- Отправленные (`pending+`) визуально отделены, без удаления.
- Футер всегда виден, пока меню свёрнуто: `+ Гость`, Печать, На кухню, Оплата. Закрытый чек — только Печать.

### Шторка меню

- Едет снизу до строки итогов (`transform`, 160–280ms ease-out). Перекрывает позиции и футер.
- Открытие: кнопка «Меню». Закрытие: «Свернуть» или свайп ручки вниз.
- Горизонтальные категории с цветами, `overflow-x: auto`.
- Плитки 2 колонки (md+: 3). Название, цена, опционально фото.
- Тап = +1 к текущему гостю, красный балун qty (scale-in).
- Корректировка `−` / `+` — только в списке позиций, не на плитке.
- Стоп-лист: серая плитка, без добавления.
- Закреплённая плитка **Произвольный товар**: имя, qty, цена на numpad, `is_custom`.

### Сплит

Не Drag-and-Drop как единственный путь на 375px (Toast: tap-and-drop).

1. `+ Гость` → чип «Гость N», имя инлайн.
2. Набор: всё на активный чип.
3. Режим «Разделить»: тап позиции → выбор гостя-получателя.
   - qty 1 — перенос целиком;
   - qty 2 — по 1;
   - qty > 2 — numpad «сколько перенести».
4. Планшет: опционально DnD между колонками гостей.
5. На оплате: **разделить поровну** (копейки; остаток от деления — первому гостю).

### На кухню

Кнопка активна, если есть `held`. Транзакция: `held` → `pending`, `sent_at`, SSE. Кухня видит только после этого.

Печать v1: `window.print()` шаблона заказа (зал, позиции, итог, QR зала).

## Оплата

1. Гостей > 1 → «Кого считаем?» (неоплаченные).
2. Способ — сегмент-переключатель Безнал | Наличные (один контрол, выбранный режим подписан).
3. Безнал: QR из `halls.qr_image_path` (`data/uploads/qr/...`, задаётся в настройках зала) над суммой + «Оплачено».
4. Нал: numpad внесено → сдача (`received - amount`), «Оплачено».
5. Не все гости оплачены → заказ остаётся `open`.
6. Все оплачены → `closed`, SSE `ORDER_CLOSED`, карточка исчезает с KDS. Просмотр закрытого чека — `/waiter/{id}`, read-only.

## Связь с KDS

В списке активных заказов: зелёная точка, если есть блюдо `ready` старше 10 с (`ready_at`). В позициях: «На кухне» до истечения 10 с, затем «Готов» зелёным. Двойной тап на KDS снимает готовность. `out_of_stock` — красный (UI кухни «нет блюда» в этом заходе нет).

## Анимации

- Шторка меню: `transform` 160–280ms ease-out, не layout thrash.
- Балун: `scale(0) → 1`.
- Не блокировать следующий тап тяжёлым JS на каждый pointermove — слушать pointer на ручке, `requestAnimationFrame`.

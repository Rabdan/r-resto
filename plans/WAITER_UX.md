# UX официанта (главный интерфейс)

Терминал официанта — основной рабочий экран R-resto. Телефон 375–430px, портрет, одна рука. Планшет — те же паттерны, плитки в 3 колонки.

Ориентиры: Toast Go (список чеков, split tap-to-move), iikoWaiter (отправка на кухню, статусы, поиск), Poster (плитки). ТЗ: [`idea_waiter.md`](../idea_waiter.md). Нельзя заменить конструктор «списком и формой».

## Принципы

- Thumb zone: главные кнопки внизу (создание, оплата, на кухню).
- Touch ≥ 48×48px.
- Цвет шапки = `halls.color_hex` активного зала.
- Тёмная база `slate-900`, высокий контраст.
- Онлайн обязателен (кухня). Офлайн-очередь не в v1.

## Экран 0 — привязка

Центр: «Привязка терминала», код `XXX-XXX` моноширинно, «Покажи этот код администратору», пульс. По SSE `DEVICE_ACTIVATED` → `/waiter` или `/kitchen`. Ссылка «Вход администратора» → `/admin` (PIN, не код устройства).

## Экран 1 — список пречеков

Как Payment Terminal Toast, под узкий экран.

- Шапка: «Привет, {имя}» | селектор зала (если залов > 1) или статичный лейбл.
- Табы: **Активные** / **Закрытые** (закрытые — только текущая смена, read-only).
- Карточка активного: №, имена гостей, 1–2 позиции превью, сумма **неоплаченного**, возраст, балуны KDS: зелёный «готово N», красный «нет блюда N».
- FAB снизу: **Создать пречек**.

Жесты карточки:

| Жест | Действие |
| --- | --- |
| Тап | конструктор |
| Свайп влево | оплата |
| Свайп вправо | печать |
| Long-press | меню: печать, +гость. Отмена — нет (только админ) |

Свайп не закрывает и не удаляет пречек.

## Экран 2 — конструктор

```
[ < ]  [Гость 1] [Гость 2] ...              зал
≡  4 поз — 1 850 ₽          ← peek шторки, тяни вниз
[поиск] [Горячие] [Десерты] [Напитки] ...
плитки 2 колонки
[Печать] [+ Гость] [На кухню] [ОПЛАТА]
```

Новые блюда всегда на **выбранный чип гостя**. Свайп чипов — смена гостя.

### Черновик пречека

«Создать пречек» открывает **черновик** (`/waiter/new`) — в БД ничего не пишется. Пречек сохраняется только при первом **«На кухню»** (`fired`) или **«Оплата»** (сразу оплата). После сохранения официант переходит на `/waiter/{id}`, и все дальнейшие изменения сохраняются автоматически (как раньше). Пустой/брошенный черновик пропадает без следа.

### Шторка заказа (обязательно)

- Peek всегда под шапкой: количество позиций, сумма текущего пречека (или выбранного гостя — подпись явная).
- Палец тянет **вниз**. Overlay поверх меню, меню не скроллится вместе с жестом (`touch-action` на ручке).
- Snap: **peek** (~48px) / **half** (~55vh) / **full**. Отпускание — к ближайшей точке. Обратный жест / тап по затемнению — свернуть (не ниже peek).
- Внутри: группировка по гостю. `+`/`−`. Свайп строки влево — удалить, **только если `held`**. Свайп вправо — перенос другому гостю.
- Отправленные (`pending+`) визуально отделены, без удаления.

### Плитки

- 2 колонки (md+: 3). Название, цена, опционально фото.
- Тап = +1 к текущему гостю, красный балун qty (scale-in).
- Long-press 300ms **или** тап по балуну → на плитке `−` / `+`.
- Стоп-лист: серая плитка, без добавления.
- Закреплённая плитка **Произвольный товар**: имя, qty, цена на numpad, `is_custom`.
- Поиск по названию над категориями.
- Горизонтальные категории, `overflow-x: auto`.

### Сплит

Не Drag-and-Drop как единственный путь на 375px (Toast: tap-and-drop).

1. `+ Гость` → чип «Гость N», имя инлайн.
2. Набор: всё на активный чип.
3. Режим «Разделить»: тап позиции → выбор гостя-получателя.
   - qty 1 — перенос целиком;
   - qty 2 — по 1;
   - qty > 2 — numpad «сколько перенести».
4. Планшет: опционально DnD между колонками гостей.
5. На оплате: **разделить поровну** (копейки; остаток от деления — первому гостю).

### На кухню

Кнопка активна, если есть `held`. Транзакция: `held` → `pending`, `sent_at`, SSE. Кухня видит только после этого.

Печать v1: `window.print()` пречека.

## Оплата

1. Гостей > 1 → «Кого считаем?» (неоплаченные).
2. Безнал: QR из `data/uploads/qr/{location_id}.*` + «Оплачено».
3. Нал: numpad внесено → сдача (`received - amount`), «Оплачено».
4. Не все гости оплачены → пречек остаётся `open`.
5. Все оплачены → `closed`, SSE `PRECHECK_CLOSED`, карточка исчезает с KDS.

## Связь с KDS

В списке и в шторке: `ready` — зелёный маркер; `out_of_stock` — красный, предложить убрать/заменить (если позиция ещё не оплачена; снятие с кухни — отдельное правило: официант не удаляет pending без админа; для oos — разрешить снять/заменить, это сигнал кухни).

## Анимации

- Шторка: `transform` 160–280ms ease-out, не layout thrash.
- Балун: `scale(0) → 1`.
- Не блокировать следующий тап тяжёлым JS на каждый pointermove — слушать pointer на ручке, `requestAnimationFrame`.
